# AI 面试助手决策记录

## 2026-06-03：作为网页小工具候选方向入池

- 决策：AI 面试助手可以挂在工具频道，作为后续 AI 能力工具候选。
- 原因：它符合工具站的办公效率、求职招聘和 AI 能力方向，也具备免费限次和付费增强空间。
- 影响：后续如果开发，应按独立工具模块接入 `/tools/ai-interview-coach`。

## 2026-06-03：第一版先做文本虚拟面试

- 决策：虚拟面试第一版使用文本问答，不做实时语音。
- 原因：文本模式成本低、兼容性高、实现路径更短，适合先验证需求。
- 影响：语音面试、实时转写和 AI 声音输出放入后续增强阶段。

## 2026-06-03：HTML 由模板渲染，不直接让模型生成整页

- 决策：大模型输出结构化 JSON，前端固定模板渲染 HTML 并下载。
- 原因：直接生成 HTML 稳定性差，结构化数据更便于测试、复盘和后续改版。
- 影响：后续实现需要定义报告 schema 和模板组件。

## 2026-06-03：不做自动招聘决策

- 决策：面试官模式只提供问题、追问、评分辅助和风险提示，不输出录用、淘汰或候选人排名。
- 原因：避免合规风险，并保持工具定位为面试辅助而非招聘决策系统。
- 影响：页面文案和报告中需要加入辅助用途说明。

## 2026-06-03：简历优化和专业实战例子后置

- 决策：简历优化、专业领域实战例子和行业用法说明作为后续增强，不放入第一版 MVP。
- 原因：第一版先验证面试作战包和文本虚拟面试闭环；简历优化会扩大到简历写作产品，需要单独设计输入、输出和风险边界。
- 影响：规划中保留扩展点，后续可拆成 `简历优化建议` 和 `专业面试素材增强` 两个任务。
