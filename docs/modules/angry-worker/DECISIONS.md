# 打工人弹射解压 — 关键决策记录

> 记录方案设计过程中做出的关键决策及其原因，供后续开发和迭代参考。

## 决策 1：Roguelike 随机关卡生成（而非手工设计）

**决策**：采用算法程序化生成关卡，而非手工设计固定关卡。

**原因**：
- 小团队无法持续产出大量手工关卡内容
- 算法一次开发，无限关卡，零后续内容生产成本
- 玩家每次进入都是新体验，极大延长生命周期
- 调整参数即可改变难度曲线，无需重新设计关卡

**影响**：
- 需要投入时间开发高质量的生成算法（Day 1-4 为核心）
- Day 5 前必须 playable test，若手感不达标需人工干预参数
- 后续迭代只需新增特殊元素和 Buff，无需设计新关卡

## 决策 2：微信小程序作为首发平台

**决策**：首发平台为微信小程序，而非独立 App 或 H5。

**原因**：
- 目标用户（打工人）使用微信频率极高
- 无需下载安装，降低体验门槛
- 微信社交链天然利于分享裂变
- 开发成本低于独立 App

**影响**：
- 必须遵循微信小程序审核规范
- 分享图不能带用户上传图片（审核风险）
- 需要使用微信云开发或自有服务器
- 后续可扩展至抖音小游戏（Phase 3）

## 决策 3：本地图片替换（不上传云端）

**决策**：用户上传的图片仅替换本地目标头部，使用 `wx.setStorageSync` 本地存储，不上传服务器。

**原因**：
- 规避肖像权和审核风险
- 分享图始终使用预置卡通形象，不带用户图片
- 无需后端存储和 CDN 成本
- 实现简单，开发成本低

**影响**：
- 换脸效果仅本机可见
- 无法跨设备同步用户自定义目标
- 需要在本地完成图片裁剪和圆形处理

## 决策 4：替换打击目标头部（而非操控角色）

**决策**：用户上传的图片替换的是被打击的"目标"（猪）头部，而非用户操控的弹射物（小鸟）。

**原因**：
- 用户想宣泄的对象是"讨厌的人/事"，自然映射到被打击目标
- 操控角色保持统一形象，降低认知成本
- 预置角色（秃头老板、凌晨甲方、改需求产品经理）提供默认宣泄对象

**影响**：
- 需要设计"目标"角色的占位结构，方便替换头部
- 本地存储以目标 ID 为 key 存储用户图片

## 决策 5：全功能保留，不砍功能

**决策**：在 1 个月开发周期内保留完整功能清单，不砍任何功能。

**原因**：
- 用户明确要求"时间无所谓，不要砍功能"
- 完整功能才能支撑"从发泄工具升级为有深度的解压游戏"
- 竞品分析显示武器差异化 + Combo + Boss + 无尽模式是"好玩"的关键分水岭

**影响**：
- 开发周期从 10 天延长到约 30 天
- 需要 3 人团队（开发 + 美术 + 策划）
- 需要更详细的进度管理和风险预案

## 决策 6：Matter.js 物理引擎

**决策**：使用 Matter.js 作为 2D 物理引擎。

**原因**：
- 轻量级，适合微信小程序性能约束
- 成熟稳定，社区活跃
- 支持刚体、碰撞、重力、弹力等核心物理特性
- 与 Canvas 2D 渲染配合良好

**影响**：
- 需要限制刚体数量 ≤ 50（低端机性能）
- 物理参数需要大量调优才能达到"爽感"
- 炸弹球爆炸效果需要自定义实现（Matter.js 不内置爆炸）

## 决策 7：IAA（激励视频广告）变现

**决策**：采用 IAA 模式，通过激励视频广告变现，不设付费点。

**原因**：
- 解压类游戏不适合强付费（破坏体验）
- 激励视频是"用户主动选择"，接受度高
- 微信小程序激励视频 eCPM 可观
- 与 Roguelike"失败即结束"机制天然契合（复活广告）

**影响**：
- 广告点位设计需要与游戏体验融合（不能太突兀）
- 需要接入微信广告 SDK
- 首月目标广告观看率 ≥ 12%

## 决策 8：3 人团队配置

**决策**：开发 + 美术 + 策划 3 人团队，开发周期约 30 天。

**原因**：
- 全功能保留需要专人负责美术和策划
- 物理手感、关卡算法、Buff 平衡需要策划深度参与
- 美术风格统一需要专职美术把控

**影响**：
- 人力成本增加，但质量更有保障
- 需要每日站会制度确保进度对齐
- Day 5 和 Day 10 是两个关键里程碑，需要 playable test

## 决策 9：分享图始终使用预置卡通形象

**决策**：分享图始终使用预置卡通角色，绝不包含用户上传的任何图片。

**原因**：
- 规避微信审核风险（用户生成内容合规）
- 规避肖像权纠纷
- 确保分享图风格统一、品牌一致

**影响**：
- 分享图生成逻辑更简单（固定模板 + 动态文字）
- 需要设计 3 个预置角色的分享图 pose
- 二维码始终指向小程序主页
