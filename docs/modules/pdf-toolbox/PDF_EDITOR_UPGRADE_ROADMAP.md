# PDF 工具箱升级规划：Edge 类阅读编辑器

**日期**：2026-06-06  
**对应任务**：T144  
**负责人**：Lee  
**状态**：待后续实现  

## 1. 结论

PDF 工具箱不应直接升级成 Acrobat 级完整 PDF 原文编辑器。第一阶段推荐升级为 `Edge 类 PDF 阅读编辑器`：以阅读、标注、添加文本、签名、遮盖、搜索和翻译为主，保留“暂不修改 PDF 内已有文字和图片”的边界。

这条路线能最快提升用户感知，同时保持免费能力成本可控。真正原文编辑、扫描件 OCR 和高质量版式还原应后置到 AI/OCR 或商业 SDK 评估。

## 2. 当前能力边界

已具备：

- PDF 上传、预览和页面缩略图。
- 页面选择、排序、旋转、删除、拆分和下载。
- 多 PDF 合并。
- 文字水印。
- 签名图片。
- 区域遮盖。
- 图片扫描成 PDF。
- PDF 转 Word Beta，当前只抽取普通文本。

仍不具备：

- 修改 PDF 内已有文字。
- 修改 PDF 内已有图片。
- 标准可编辑批注层。
- 高亮选中文本。
- 画笔和便签。
- PDF 内文本搜索。
- 选中文本翻译。
- OCR 识别扫描件。
- 高质量压缩和高质量版式还原。

## 3. 产品定位

推荐命名：

## 5. 分阶段路线

### 阶段 A：Edge 类免费标注编辑

目标：让用户获得“能在 PDF 上编辑”的直观体验，但技术上仍是叠加层或保存副本。

功能：

- 新增阅读器模式，支持缩放、页码跳转和连续滚动。
- 添加文本框，支持拖拽、字号、颜色和删除。
- 签名图片支持拖拽放置到指定页面，而不是固定右下角。
- 区域遮盖支持拖拽、调整尺寸、选择颜色和应用到当前页或全部页。
- 高亮选中文本。
- 画笔和清除画笔。
- 保存为新 PDF。

技术：

- 使用 `PDF.js` 渲染页面。
- 在每页 canvas 上方放置 annotation overlay。
- 前端用 JSON 记录每个批注的页面、坐标、尺寸、样式和内容。
- 第一版保存时用 `pdf-lib` 将批注 flatten 到新 PDF。

验收：

- 用户可以上传 PDF 后添加文本、签名、遮盖和高亮。
- 下载的新 PDF 在 Edge、Preview 和常见 PDF 阅读器中可见。
- 移动端可以完成最小签名和遮盖操作。

### 阶段 B：文本搜索、抽取和翻译

目标：补齐 Edge 类文本辅助能力，并为 AI Gateway 接入建立试点。

功能：

- PDF 文本搜索。
- 选中文本复制。
- 选中文本翻译。
- 当前页翻译。
- 全文抽取预览。
- 翻译结果复制和导出。

技术：

- 复用 `PDF.js getTextContent()`。
- 建立文本 item 坐标映射，用于搜索命中和高亮定位。
- 翻译能力后续走 AI Gateway capability，例如 `pdf.translate.selection` 和 `pdf.translate.page`。
- 未接真实模型前可提供本地占位或隐藏入口。

验收：

- 普通文本 PDF 可以搜索关键词并定位页面。
- 选中文本可以进入翻译侧栏。
- 扫描件明确提示需要 OCR。

### 阶段 C：办公转换增强

目标：继续覆盖搜索刚需，提高工具入口流量。

功能：

- PDF 转图片。
- 基础压缩。
- PDF 转 Word Beta 质量提示优化。
- 图片转 PDF 的排序和页面尺寸选项。
- 批处理入口占位。

技术：

- PDF 转图片使用 PDF.js 渲染页面后导出 PNG/JPEG。
- 基础压缩优先做图片重采样和保存策略，不承诺极致压缩率。
- 大文件或高质量压缩后续再进入服务端任务。

验收：

- 用户可以选择页面导出为图片。
- 用户可以获得压缩后文件，并看到压缩前后大小。
- 大文件失败时提示浏览器内存限制。

### 阶段 D：原文编辑和商业 SDK 评估

目标：只做评估，不进入第一批实现。

评估对象：

- Apryse。
- Nutrient。
- Adobe / Acrobat 相关方案。
- 其他支持 Web PDF 原文编辑的商业 SDK。

评估维度：

- 是否支持修改 PDF 内已有文字。
- 是否支持替换图片。
- 是否支持移动、删除和编辑已有对象。
- 是否支持中文字体和复杂版式。
- 是否支持浏览器端处理。
- 授权成本和商用限制。
- 文件是否需要上传服务端。
- 是否能和现有 Next.js 模块集成。

决策线：

- 如果目标只是免费流量和轻编辑，不接商业 SDK。
- 如果要做会员级专业 PDF 编辑，再单独立项商业 SDK 方案。

## 7. 风险

- 坐标系统复杂：PDF 坐标、canvas 像素、缩放比例和移动端触控需要统一换算。
- 标准批注兼容性复杂：第一版建议 flatten 到 PDF，避免不同阅读器兼容差异。
- 翻译和 OCR 有成本：必须纳入 AI Gateway、限次或积分策略。
- 原文编辑容易失控：不应在没有商业 SDK 或清晰商业价值前自研。
- 移动端操作难度高：签名、遮盖和文本框必须优先设计触控交互。
