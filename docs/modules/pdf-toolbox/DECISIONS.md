# PDF 工具箱决策记录

## 2026-05-21：不做完整 PDF 原文编辑

- 决策：第一版只做页面级处理和转换，不做完整 PDF 原文在线编辑。
- 原因：完整编辑技术复杂度和商业 SDK 成本高，不适合作为第一阶段 MVP。
- 影响：页面处理使用 `pdf-lib`，预览使用 `PDF.js`；文案必须避免承诺可修改 PDF 内已有文字和图片。

## 2026-05-21：代码使用独立模块目录

- 决策：PDF 工具箱业务代码放在 `apps/web/src/modules/tools/pdf-toolbox/`。
- 原因：后续小工具数量会增加，独立模块目录更利于筛选、维护和交接。
- 影响：`apps/web/src/app/tools/pdf-toolbox/page.tsx` 只做路由入口，不承载业务逻辑。

## 2026-05-21：PDF 去水印只做自有文件区域遮盖

- 决策：第一版不做破解式或 AI 智能去水印，只提供白色矩形区域遮盖，用于处理用户自己 PDF 中不需要的水印、遮挡或局部元素。
- 原因：当前阶段不调用模型能力，也不能引导移除他人版权标识或绕过 PDF 权限。
- 影响：UI 文案必须明确“不用于移除他人版权标识”；后续如做智能去水印或 OCR，需要重新进入 AI/OCR 能力规划。
