Cocos 正式游戏 v1

从功能样机收口成一款能完整开局、学习、构筑、失败恢复、挑战 Boss、结算并再次游玩的正式游戏。

核心决策

Cocos 是唯一正式运行时。冻结 Web demo 的玩法扩展，先交付一个 20–30 分钟完整章节，再扩长期模式。

1 个首发完整章节
10 个教学/普通/事件/精英/Boss 节点
20–30 分钟一次完整游玩
5–7 周单主开发 + 兼职 UI/音频
0 个 P0/P1上线允许遗留的严重缺陷
现状判断 v1 产品边界 完整玩家旅程 章节内容 目标架构 UI 与音频 分阶段路线 上线质量门禁 实施批次 完成定义

这不是“再补几个按钮”就能解决

Cocos 已有大量玩法能力，但入口、规则真相源、流程、UI、音频、存档和构建没有形成一条可发布链路。继续按功能追平 Web，只会扩大分叉。

结构

3501 行主控制器

UI、规则 fallback、流程、存档和账号桥接混在一起，修改风险跨越整个游戏。

体验

只有一份 Scene

正式菜单、弹层、组件状态和动效没有 Prefab/Animation 管线，界面仍像运行时拼装壳。

声音

音频资产与系统均为空

吃碰杠胡、危局、奖励和 Boss 没有听觉层级，操作缺少重量和完成感。

内容

Web 与 Cocos 双真相源

关卡、奖励、规则和生成器已分叉，功能对等并不等于行为一致。

资源

127 MB assets 未治理

首屏依赖、未使用模块、概念图与正式资产没有清晰发布边界。

构建

产物成功，CLI 返回 36

fresh web-mobile build 已生成 index.html；发布门禁必须同时校验日志、产物和 HTTP smoke。

判断：保留现有玩法资产，冻结新增模式，先重建一个可发布骨架和完整章节。

v1 产品边界

首发版本追求纵向完整，不追求功能总量。玩家不登录、不付费，也能完成一整轮并获得明确复盘。

正式包含
  • 标题、继续、新游戏、设置、暂停、错误恢复
  • 10 节点章节与 90 秒内嵌教学
  • 8 格主槽、1 格备用槽、牌河、记牌器
  • 手动吃/碰/杠/补杠/胡与候选选择
  • 洗牌、撤回、弃牌三工具
  • 12 奖励、一次事件、精英与 Boss
  • 本地继续、三检查点、失败与通关结算
  • 正式 UI、动效、3 BGM、18 SFX
首发后置
  • 无尽、高阶、每日、完整成就图鉴
  • 开局六流派和复杂局外升级树
  • 账号跨端同步、排行榜、多人
  • 体力、付费和商业化
  • 完整麻将番型与算番
  • 低质量人物 cut-in
  • Web demo 与正式版功能追平

完整玩家旅程

任何一次中断都有确定去向，任何一次失败都有原因与恢复点，任何一次通关都能自然再开一局。

Boot校验资源、配置、存档
Title继续 / 新游戏 / 设置
Learn前两场内嵌教学
Build牌局、奖励、事件、检查点
Boss杠、胡、清台三目标
Result复盘 / 再来一局 / 标题
90 秒

第一次理解规则

先点击自由牌，再手动发动第一次碰；第二场才引入遮挡、吃和多候选。

稳定存档

每次结算后保存

不保存动画中间态。坏档先回最近检查点，再回标题，不让玩家白屏。

失败复盘

告诉玩家为什么输

展示原因、最近 5 次关键操作、构筑和距检查点位置，并提供三个明确去向。

十节点章节

章节用三次奖励形成节奏锚点，Boss 前只引入已经教过的规则，不在终局临时增加新系统。

节点类型主要职责时长
1–2教学牌局自由牌、入槽、碰、遮挡、吃、多候选4–5 分钟
3普通牌局杠与记牌器，结束后奖励 + 检查点 A2–3 分钟
4–6普通牌局8 格压力、备用槽、胡、工具取舍，奖励 + 检查点 B7–9 分钟
7事件安全小收益 / 风险大收益二选一1 分钟
8精英牌局双目标、低容错、构筑验证3–4 分钟
9普通牌局Boss 前压力，最终奖励 + 检查点 C2–3 分钟
10Boss完成一次杠、一次胡并清空牌山4–5 分钟
内容门槛：正式 seed 全部通过可解性验证；保证至少一条合法通路，不保证任意错误操作都可挽回。

从“大控制器”变成可测试游戏

规则、流程、渲染、存档与资源各自只有一个职责。表现层提交命令、消费快照，不再自行判断能不能胡。

唯一规则

纯 TypeScript domain

放在 Cocos 工程内且不依赖 cc，仓库测试直接导入，避免工程外 import 和本地复制。

唯一内容

版本化 resources JSON

章节、奖励、教程、事件、音频和 UI key 在 Boot 一次性校验，坏配置不带病运行。

渐进迁移

先特征测试，再逐项迁出

每迁出一项就删除旧 fallback，不做一次性推倒重写。

取舍现有内容动作
保留牌资源、遮挡、槽位、牌河、记牌器、工具、手动组合语义固定 seed 与特征测试保护后迁入唯一 domain
重建App/Run Flow、内容、存档、音频、Scene/Prefab、发布用新接口逐项替换 Controller 职责
隐藏无尽、高阶、每日、成就、复杂成长、账号同步feature flag 默认关闭，不进入生产回归
删除规则 fallback、demo 生产入口、重复 generator、动态整页 UI新路径通过等价测试后同批移除

UI、音频与反馈是首发功能

视觉采用漆木、青玉、象牙牌面、漆红危险和克制金色奖励。正式 UI 全部在 Cocos Scene/Prefab 中，DOM 只负责宿主。

UI 交付

4 Scene + 15 类 Prefab

Boot、Title、Game、Result；HUD、Tile、Slot、ComboBar、ToolDock、Counter、Objective、Modal、Reward、Event、Pause、Settings、Toast 等组件。

  • 补齐正式胡按钮和五类组合完整状态
  • 390x844 主设计，桌面保持竖屏比例
  • 44x44 最小点击目标，安全区和横屏暂停
  • 不使用长说明卡遮挡牌山
声音与动效

3 BGM + 4 Stinger + 18 SFX

标题、普通、Boss 三套音乐；吃碰杠胡、工具、危局、目标、奖励和 UI 都有可区分反馈。

  • master / music / sfx 三总线
  • 首个手势解锁，后台淡出与恢复
  • 减弱动效移除震屏和长位移
  • 音频与字体强制许可证清单

5–7 周分阶段路线

每一阶段都交付可运行软件并设置退出标准。任何阶段未通过，就不把范围继续推向下一阶段。

M0

止血与可重复基线 · 2–3 人日

冻结 Web demo，收口 T239/T240，golden seed/截图，build wrapper、版本文件、HTTP smoke、keep/hide/delete 清单。

退出：干净环境可重复生成并启动 production build
M1

核心边界与状态机 · 5–7 人日

GameSession、RunStateMachine、Coordinator、ContentRepository、SaveService；逐项移除 Controller 规则职责。

退出：同一 seed 无渲染可复现，只有一条规则路径
M2

三节点纵切 · 5–7 人日

标题、教学、奖励、mini Boss、失败、继续、结算；最终 Prefab 骨架和第一版音频链路。

退出：手机/桌面 production build 可玩 8–12 分钟闭环
M3

完整十节点章节 · 5–7 人日

12 奖励、事件、精英、正式 Boss、三检查点、确定性 seed、20 局平衡记录。

退出：章节中位时长 20–30 分钟，无不可解正式 seed
M4

正式 UI、音频与反馈 · 6–9 人日

正式资产、按钮状态、动效、3 BGM、18 SFX、设置、减弱动效和许可证清单。

退出：无概念图/调试文字/缺状态按钮，音画反馈完整
M5

性能、QA 与上线 · 4–6 人日

资源分组、引擎裁剪、设备矩阵、坏档恢复、埋点、部署清单、回滚包和版本说明。

退出：全部质量预算达标，目标设备完成全流程

上线质量门禁

质量门槛在开发前锁定，避免最后一周才发现包体、音频、存档和真机问题。

首屏压缩下载 ≤ 15 MB完整章节压缩下载 ≤ 35 MB，Boss 与 BGM 分组加载。
标题可操作：桌面 ≤ 4 秒，Fast 4G ≤ 8 秒真实 production build 通过 HTTP 测量。
中位帧率 ≥ 55 FPS1% low ≥ 30 FPS，点击首反馈 ≤ 100 ms。
移动端峰值内存 < 300 MB连续重试三次无持续增长。
正式 seed 全部可解100 个候选 seed 自动求解；正式集合全部通过。
存档可迁移、坏档可恢复原子写入、版本迁移、quarantine、检查点 fallback。
P0 / P1 缺陷 = 0资源 404、未处理异常、开发入口、占位资产 = 0。
5 组视口 + 4 类设备手机 Safari/Chrome、桌面 Safari/Chrome/Edge 全流程。

代码级实施批次

书面规格确认后再写每个批次的精确文件、接口、失败测试、验证命令和提交边界。

01–02

发布基线 + 唯一规则路径

冻结 demo，build wrapper；给旧行为加特征测试，建立 GameSession，删除 Controller fallback。

03–04

流程状态机 + 内容仓库

Coordinator、App/Run Flow；十节点 schema、奖励、事件、seed 和资源 key 校验。

05–06

存档恢复 + 正式 UI 骨架

检查点、迁移、坏档；Scene/Prefab、安全区和响应式布局。

07–08

纵切 + 完整章节

先交付三节点 production 闭环，再扩十节点和 20 局平衡。

09

UI 资产、动效、AudioService

完成正式资产、状态、动效、音频总线、授权和后台行为。

10

性能、兼容、发布与回滚

体积、FPS、内存、E2E、埋点、版本清单、部署验证和回滚包。

立即停止：不再给 Web demo 加玩法；不在 GameSceneController 中继续拼整页 UI；不在 v1 前开放新模式；不让未授权或未完成状态资产进入 production。

什么才算“完整上线可玩”

不是“功能都能点”，而是玩家、代码、内容和发布四条链同时闭环。

玩家

无需外部说明

能从标题完成教学、十节点、Boss、结算，并理解失败与恢复。

代码

唯一规则路径

规则、流程、内容、存档、渲染边界清楚，Web demo 不参与生产。

音画

无开发占位

Scene/Prefab、正式 UI、动效、BGM、SFX、设置和授权完整。

发布

可重复、可验证、可回滚

构建、设备、性能、存档、埋点、版本和回滚全部有门禁。
