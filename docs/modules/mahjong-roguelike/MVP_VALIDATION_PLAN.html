T042 · 验证稿 v0.1 · 2026-05-23

麻将 Roguelike MVP 玩法验证计划

先验证核心体验是否成立，再决定是否继续扩关卡、扩模式和扩长期系统。这个版本只看“能不能玩、好不好懂、值不值得做”。

最小闭环验证 先测 3 个场景 不做完整 20 关 验证通过后再冻结 MVP

1. 要验证什么

核心动作

点牌、入槽、手动发动

玩家是否能自然理解 `点牌 -> 入槽 -> 按钮点亮 -> 手动吃碰杠`。

策略压力

槽位会不会逼出决策

玩家是否会停下来判断，而不是只顾连续点牌。

信息层

余牌是否真的有用

玩家会不会基于余牌改变路线，而不是只看装饰效果。

构筑感

奖励能不能改打法

3 选 1 之后，玩家是不是会开始记住自己的本局风格。

2. 最小闭环

1. 选牌点击未被覆盖的牌。
2. 入槽进入主槽，输入锁定。
3. 识别显示候选组合和余牌。
4. 发动玩家手动点吃、碰、杠。
5. 反馈过关、奖励、救场或失败。

3. 验证场景

场景要看什么如果不成立
单一组合按钮是否一眼能懂先简化按钮文案和高亮规则
多组合冲突玩家会不会自己选，而不是等系统替他选先减少候选类型
满槽危局救场顺序是否合理，失败是否公平先放宽初始槽位或降低密度
余牌决策玩家是否会拿余牌做判断先只保留花色总数
奖励选择奖励是否改变下一局打法先把奖励改成路线型

4. 观察标准

理解度

1 分钟内能否复述循环

测试者能不能说出“点牌、入槽、按钮、奖励、失败”的基本流程。

决策感

会不会真的比较候选

出现多组合时，玩家是否愿意自己做选择。

构筑感

奖励有没有改变下一步

奖励不是单纯数值，而是让下一局的打法变了。

如果玩家完全不看余牌、不看奖励、不看槽位，那说明玩法的策略层还不够清楚，不该直接进正式开发。

5. MVP 冻结线

冻结： - 万 / 条 / 筒 - 手动 吃 / 碰 / 杠 - 主槽、备用槽、满槽护符 - 局内积分、铜钱、余牌 - 洗牌 / 撤回 / 透视 - 10 个验证关卡 - 10 个局内奖励 - 3 个局外升级 暂缓： - 20 关完整节奏 - 每日牌局 - 无尽牌山 - 高阶周目 - 排行榜 - 复杂成就 - 完整番型

6. 验证出口

通过后，进入正式开发计划拆分，先做规则模型和关卡配置。
不通过时，回到最弱的一条假设做局部修正，再重新测试。
验证目标不是把所有功能做完，而是确认这个核心循环值不值得继续投资源。
