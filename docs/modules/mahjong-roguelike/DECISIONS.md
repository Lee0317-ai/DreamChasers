# 麻将 Roguelike 消除决策

## D001：使用双工程 + 共享配置路线

- 日期：2026-05-21
- 状态：建议，待玩法讨论后确认
- 决策：规则和配置保持引擎无关；GDevelop 可用于 Web H5 原型；Cocos Creator 用于正式小游戏工程；Next.js 只做站内嵌入和事件接收。
- 原因：避免 Web 原型、正式小游戏和站点入口三套逻辑割裂。
- 影响：T017 实现前应优先建立 `packages/shared` 规则模型和 JSON 配置。

## D002：第一版不实现完整麻将算法

- 日期：2026-05-21
- 状态：已确认
- 决策：第一版只做 `碰 / 吃 / 杠 / 清一色 / 胡牌目标` 的轻量化消除规则。
- 原因：降低用户学习成本和实现复杂度。
- 影响：复杂番型、听牌、算番、真实麻将局流程全部后置。

## D003：消除必须由玩家手动发动

- 日期：2026-05-22
- 状态：已确认
- 决策：槽位中的牌不会自动消除。系统只检测 `吃 / 碰 / 杠` 是否可用，并把对应按钮从灰色切换为金红冒火状态；玩家点击按钮后才发动消除。
- 原因：手动发动更有麻将手感，也能形成选择压力和策略判断，避免游戏退化成普通自动合成。
- 影响：规则模型需要区分“检测可用组合”和“执行组合”；失败判定需要在槽位满且没有可发动组合时才触发。

## D004：槽位作为局外成长核心

- 日期：2026-05-22
- 状态：建议，待数值验证
- 决策：槽位不只是容量，而是局外养成核心。玩家通过软货币升级槽位容量、备用槽和槽位净化等属性。
- 原因：槽位成长可以自然降低难度，给玩家长期目标，同时不破坏第一阶段免费原则。
- 影响：奖励、道具和关卡难度需要围绕槽位压力重新平衡。

## D005：最终模式结构

- 日期：2026-05-22
- 状态：已确认
- 决策：最终结构采用 `闯关模式`、`无尽牌山`、`高阶周目`、`每日牌局`、`成就图鉴`。
- 原因：20 关首通只能解决新手目标，不能承载长期挑战；无尽层数、高阶周目、每日固定牌局和成就收集可以分别提供挑战、深度、回访和收集目标。
- 影响：关卡配置需要支持固定 20 关、无尽层生成、周目词缀、每日种子和成就条件；UI 需要预留模式入口和通关后解锁反馈。

## D006：高阶挑战由多种压力组成

- 日期：2026-05-22
- 状态：已确认
- 决策：高阶挑战采用 `牌山层数增长 + 词缀系统 + 随机事件 + 卡槽压缩 + Boss 试炼`，不只靠增加牌数或堆叠层数。
- 原因：单纯增加堆叠会让游戏变长但不一定更好玩；限制能力、改变规则和加入选择事件能提供更稳定的挑战感和新鲜感。
- 影响：后续配置需要支持词缀、事件、试炼和能力禁用；UI 需要清楚展示当前词缀、事件选择和被限制的能力。

## D007：组合提示和牌堆生成规则

- 日期：2026-05-22
- 状态：已确认
- 决策：`吃 / 碰 / 杠` 只要出现合法组合就提示，并展示对应消除内容；多个组合时允许玩家选择具体组合。后续高阶挑战支持玩家手动选择 3-4 张牌再发动。牌堆使用组合包受控随机生成，不要求完整麻将牌组，可以同花色重复。
- 原因：组合提示保证基础可读性，组合选择保留策略；受控随机保证牌局有解但不死板；不使用完整麻将牌组可以服务关卡节奏和难度曲线。
- 影响：规则模型需要区分组合检测、组合候选列表、玩家选择和执行；关卡生成器需要支持吃包、碰包、杠包、目标包和干扰包。

## D008：孤张必须有消化机制

- 日期：2026-05-22
- 状态：已确认
- 决策：如果玩家提前 `碰` 掉本可 `杠` 的牌，导致剩余 1 张孤张，系统不直接判错，但需要提供后续补牌、备用槽、弃牌符、换牌、杠后补牌或特定关卡豁免等消化方式。
- 原因：保留 `碰` 和 `杠` 的策略冲突，但避免玩家觉得游戏制造无法处理的死牌。
- 影响：奖励、道具和关卡目标需要预留孤张处理能力；可解性校验只保证初始至少一条可解路径，不保证任意操作都能过。

## D009：顶部牌谱记牌器

- 日期：2026-05-22
- 状态：已确认
- 决策：游戏顶部新增 `余牌/牌谱记牌器`。默认显示 `万 / 条 / 筒` 剩余总数，展开后显示 1-9 点数剩余数量；消除后实时减少。
- 原因：记牌器能让玩家判断是否等待 `杠`、是否继续追顺子、孤张是否还有补牌机会，从而减少盲猜并提高麻将策略感。
- 影响：UI 需要预留顶部简版和展开层；规则状态需要维护剩余牌计数；透视仍保留，因为记牌器只显示数量，不显示位置。

## D010：局内能力池按流派分层

- 日期：2026-05-22
- 状态：已确认
- 决策：局内 Roguelike 能力池按孤张/补牌/换牌、杠流、吃流、碰流、花色流、槽位流、道具流、信息流 8 类组织。
- 原因：每类能力解决不同问题，能让一轮牌局形成不同构筑；孤张和补牌能力优先级最高，因为它们负责处理手动策略带来的残牌后果。
- 影响：后续能力配置需要带 `type`、`rarity`、`effect`、`tags`、`conflicts` 等字段；直接移除牌、补牌、换牌能力需要受稀有度和数量限制。

## D011：永久能力分层与局内能力分离

- 日期：2026-05-22
- 状态：已确认
- 决策：永久能力分为 `基础成长`、`固化能力`、`起局能力`、`道具强化` 四层；其中基础成长自动生效，不占能力卡槽，其余三层都需要装备。局内能力仍保持每过关 3 选 1，只在当前一轮牌局内生效。
- 原因：把局外成长、开局构筑、工具强化和局内奖励拆开后，玩家更容易理解每种能力的用途，也更容易后续平衡。
- 影响：能力配置需要明确 `slotType` 和 `scope`；UI 需要区分永久成长页、开局装备页和局内奖励选择。

## D012：手牌槽位与能力卡槽分开管理

- 日期：2026-05-22
- 状态：已确认
- 决策：`手牌槽位` 负责底部放牌容量和容错，`能力卡槽` 负责装备永久能力。高阶周目默认压缩能力卡槽，不直接等同于减少手牌槽位。
- 原因：手牌槽位承载基础难度，能力卡槽承载构筑难度；两者分离后，玩家能理解高阶挑战到底是在压容量、压 build，还是压信息。
- 影响：高阶词缀、Boss 试炼和周目规则需要写清限制对象；`透视` 归入道具强化，不等于扩槽。

## D013：完整牌局输入状态机

- 日期：2026-05-22
- 状态：已确认
- 决策：只有未被上层牌覆盖的牌可点击；牌入槽动画期间锁定输入；入槽后不能手动撤销，只能用 `撤回` 道具；玩家点击合法 `吃 / 碰 / 杠` 按钮后立即发动，不做二次确认。
- 原因：输入边界明确后，才能避免满槽、动画、撤回和组合发动之间出现状态歧义。
- 影响：规则模型需要有 `idle`、`tile_entering`、`combo_selecting`、`danger_check`、`resolving` 等状态；UI 需要在动画和危局时禁用不合法操作。

## D014：组合候选由玩家自由选择

- 日期：2026-05-22
- 状态：已确认
- 决策：多个合法组合同时存在时，系统展示候选组合，但不替玩家选择最优解；玩家可以选择候选组合，也可以手动选择 3-4 张槽内牌，只有满足条件时对应按钮可用。
- 原因：`吃 / 碰 / 杠` 的冲突选择是麻将手感和策略感的来源，不能被系统自动消掉。
- 影响：规则模型需要输出候选组合列表；UI 需要支持候选选择、槽内手动选择和按钮可用态联动。

## D015：双层收益和体力系统

- 日期：2026-05-22
- 状态：已确认
- 决策：组合收益先给 `局内积分`，用于本轮购买洗牌、撤回、透视等局内资源；过关、无尽层数、成就、每日和后续排行奖励给 `铜钱`，用于永久升级。每局正式牌局消耗 5 点体力，体力上限 100 点，可按时间恢复，也可用铜钱或付费购买。
- 原因：局内积分负责当局决策，铜钱负责长期养成；体力承接回访和商业化，但不应限制新手引导和低成本试玩。
- 影响：旧规划中“组合直接给铜钱”的口径需要改成局内积分；局外成长和体力购买使用铜钱。

## D016：失败前救场顺序

- 日期：2026-05-22
- 状态：已确认
- 决策：主槽满后按 `组合检测 -> 备用槽自动救场 -> 满槽护符 -> 救场道具窗口 -> 首败保护 -> 失败结算` 的顺序处理。不允许复活；失败后局内能力和局内积分清空。
- 原因：先保留玩家手动组合选择，再消耗低破坏性的容错资源，最后才清牌或失败，能减少误判挫败。
- 影响：备用槽、满槽护符、撤回、弃牌符、换牌、首败保护都要进入同一套危局判定流程。

## D017：孤张只做内部判定

- 日期：2026-05-22
- 状态：已确认
- 决策：系统内部可以定义 `暂时孤张` 和 `死孤张`，但不直接在牌面上标记给玩家；玩家通过记牌器、候选组合和道具提示判断风险。
- 原因：直接标记会削弱记牌器和判断空间；内部判定又是满槽护符、备用槽自动救场和孤张能力的必要基础。
- 影响：实现时需要保留内部孤张评分，但 UI 默认不显示 `孤张/死孤张` 标签。

## D018：先做最小可玩验证原型，再进入正式 MVP

- 日期：2026-05-23
- 状态：已确认
- 决策：T042 和 T043 之后不直接进入完整 T017 实现，先新增并完成最小可玩验证原型。原型只覆盖 3-5 个场景，验证手动 `吃 / 碰 / 杠`、槽位压力、余牌价值、局内奖励和失败救场是否成立；验证通过后再进入规则模型、配置生成器和 Cocos 核心场景。
- 原因：玩法规划内容已经较完整，如果跳过验证直接开发完整 MVP，容易把 20 关、无尽、高阶、每日、成就和长期成长一起塞进第一版，导致周期失控。
- 影响：后续建议先拆 `T044：麻将 Roguelike 最小可玩验证原型`；T017 正式 MVP 范围只冻结 10 关、10 个局内奖励、3 个基础道具和 3 个局外升级。
