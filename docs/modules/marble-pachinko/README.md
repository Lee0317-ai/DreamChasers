# 弹珠机福利玩法

> 一句话：把线下弹珠机的拉杆、钢珠轨迹、亮灯倍率和命中奖励感，改造成 DreamChasers 里的轻量放松游戏和平台福利活动。

## 1. 产品定位

弹珠机福利玩法不是第一阶段核心交付模块，而是后续候选的留存小游戏。它的价值在于：

- 给用户在使用 PDF、修图、TimePick、AI 能力之外提供短时放松内容。
- 用物理弹射、亮灯轨道、倍率展示制造爽感和回访动力。
- 作为平台福利活动承接充值赠送、签到、任务奖励和 AI 体验积分。

它不应被设计成 AI 积分下注系统。AI 积分可用于网站 AI 能力，具有服务价值；如果允许用户消耗可购买积分参与随机倍率返还，会显著提高合规和产品信任风险。

## 2. 核心玩法草案

```text
获得 playTickets
  -> 选择一局弹珠机
  -> 机器展示倍率和亮灯轨道
  -> 用户拖拽或拉杆发射钢珠
  -> 钢珠经过钉阵、轨道和挡板碰撞
  -> 落入亮灯轨道则结算奖励
  -> 奖励进入 bonusCredits、gameCoins 或装饰资产
```

## 3. 资产分层

| 资产 | 来源 | 用途 | 是否可用于弹珠机 |
| --- | --- | --- | --- |
| `paidCredits` | 用户购买或充值 | 消耗 AI 能力 | 否 |
| `bonusCredits` | 平台活动赠送 | 体验 AI 能力 | 否 |
| `playTickets` | 充值赠送、每日任务、签到 | 游玩弹珠机 | 是 |
| `gameCoins` | 游戏内获得 | 皮肤、装饰、排行榜 | 是，仅游戏内 |

关键原则：

- `paidCredits` 只能购买确定性的 AI 服务，不参与概率游戏。
- `bonusCredits` 可用于 AI 能力，但不能再次用于游戏。
- `playTickets` 不能转让、不能提现、不能兑换现金或礼品卡。
- `gameCoins` 只在弹珠机模块内部循环，不进入 AI 能力账户。

## 4. 两种商业方式评估

### 4.1 充值送游戏次数

推荐作为优先探索方向。

```text
用户充值 AI 积分
  -> 获得 paidCredits
  -> 额外获得少量 playTickets
  -> 使用 playTickets 游玩
  -> 命中奖励 bonusCredits、gameCoins、皮肤或徽章
```

这种方式的关键是让用户购买的主要商品始终是 AI 积分，弹珠机次数只是附赠福利。奖励需要设置每日上限，并且不能返还 `paidCredits`。

### 4.2 直接购买游戏次数

不建议第一阶段做。

如果后续一定探索，必须满足：

- 每次购买都有确定性保底权益。
- 随机奖励不返还 `paidCredits`。
- 奖励优先限定为纯游戏装饰、`gameCoins` 或低额 `bonusCredits`。
- 上线前必须做法务和合规确认。

## 5. 不做范围

- 不做现金、提现、转售、回购。
- 不做礼品卡或可变现奖品。
- 不做 `paidCredits` 随机倍率返还。
- 不做未成年人可无限游玩的概率奖励。
- 不做排行榜现金化或实物权益竞争。
- 不绕过平台账号、积分和审计记录。

## 6. 后续技术方向

- Web 原型可用 Canvas 2D 或 Matter.js 实现弹射、碰撞、轨道和钉阵。
- 正式站内游戏接入使用 `apps/web/src/modules/games/marble-pachinko/`。
- 后续如果需要小游戏发布，再评估 Cocos 或 GDevelop。
- 奖励、票券和积分记录必须接入平台资产层，而不是写在单独本地状态里。
