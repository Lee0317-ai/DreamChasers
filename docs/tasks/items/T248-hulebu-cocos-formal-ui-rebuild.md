## 目标

以用户提供的胡了卜参考图为唯一视觉基准，重做一套能进入正式 Cocos 工程的固定竖屏 UI。最终交付不是一张整图，而是保持同一材质、比例和层级的可交互资源集合。

## 第一阶段范围

- 青绿主场景皮肤一套：背景、桌面、装饰、边框和可安全覆盖区域。
- 局内 HUD：关卡牌匾、分数牌匾、余牌/记牌器、牌河、8 格手槽。
- 动作按钮：吃、碰、杠、补杠、胡的普通/按下/禁用状态。
- 工具按钮：洗牌、撤回、提示、Buff、展开记牌器的普通/按下/禁用状态。
- 内容卡片：奖励三选一、教学、多候选、暂停、结算弹窗。
- 统一资源清单：尺寸、透明边界、锚点、SpriteFrame key、九宫格或裁切规则。

## 不做

- 不做横屏或多分辨率适配。
- 不同时制作东/南/西/北四套完整风场皮肤；风场卡只保留可复用卡片模板和首套内容。
- 不修改玩法规则、M2 App Flow、存档、音频或微信小游戏平台接入。
- 不把参考图整张作为运行时交互层；所有可点击元素必须拥有独立 SpriteFrame 或 Prefab 节点。

## 视觉基线

- 构图：主牌山居中，顶部信息区、右侧工具列、底部动作区和牌槽保持参考图的相对关系。
- 材质：青绿玉石/漆面、暖米色牌面、深木托盘、低饱和金色边线；按下态使用暖橙火焰，不使用纯红高亮。
- 文字：中文标题与按钮字统一使用可授权的高可读字体或已栅格化字形；避免临时系统字体直接混入最终贴图。
- 状态：普通、按下、禁用必须有明显但克制的差异；禁用态降低亮度和饱和度，不改变控件几何边界。
- 画布：以 `390×844` 为唯一验收尺寸，资源按设计像素输出，Cocos 运行时只做比例缩放，不重新排版。

## 资源分层

1. `background/`：主场景皮肤和安全区。
2. `hud/`：牌匾、计数器和信息条。
3. `board/`：牌山底板、牌河、手槽和槽位装饰。
4. `actions/`：吃/碰/杠/补杠/胡三状态。
5. `tools/`：洗牌/撤回/提示/Buff/记牌器三状态。
6. `cards/`：奖励卡、风场卡、教学卡。
7. `modals/`：教学、多候选、暂停、设置和结算底板及标题。
8. `tiles/mahjong/`：34 张正面和 1 张背面，统一牌体、符号比例和透明边界。

## Cocos 接入边界

- 资源生成脚本只负责输出 PNG、manifest 和校验报告，不写入 Cocos `library/`、`temp/` 或 `build/`。
- Cocos 导入后以 manifest 建立 `tileKey -> SpriteFrame` 映射；Binder 只消费语义 key，不按文件路径猜测资源。
- UI Prefab 负责节点层级、锚点和九宫格；Controller/Binder 负责状态和文本，不负责绘制资源。
- 首次接入只替换 M2 需要的主场景和局内 HUD，不重写既有玩法逻辑。

## 验收标准

- 资源检查：PNG 为 UTF-8 无关二进制资源；无多余不透明边缘、无明显裁切缺陷、无 `__pycache__`/`.DS_Store` 等临时文件进入交付包。
- 一致性检查：同一组控件尺寸、圆角、边线、阴影和文字基线一致；三态可区分但不跳位。
- Cocos 检查：`390×844` production 包中主场景、牌山、手槽、动作栏、工具栏和弹窗均可见；点击层与视觉层对齐；控制台无未处理错误。
- 审美检查：与参考图的主色、材质、构图和信息层级一致；不再出现当前 v6 的“零散组件拼贴”观感。
