# 打工人弹射解压 — 解决方案

## 版本
v1.0 — 2026-05-25

---

## 执行摘要

### 一句话描述
一款面向打工人的微信小程序解压游戏，用简化的物理弹射玩法击毁"职场公敌"，配合搞笑吐槽和分享裂变，半个月内完成可运行Demo。

### 核心主张
打工人的情绪宣泄需求真实且高频，但现有解压游戏要么"无脑暴力"缺乏共鸣，要么"模拟经营"缺乏爽感。我们将弹球类游戏的即时破坏爽感与职场吐槽的内容共鸣结合，创造一个"既能发泄又能笑出声"的差异化体验。

### 关键指标（预期）
- **Demo阶段**：3个可玩关卡，弹射-命中-吐槽-分享核心循环跑通
- **上线验证**：单局时长>30秒，分享率>10%，审核一次通过
- **增长目标**：上线首月DAU 5000+

## 一、问题与机会

### 1.1 问题定义

打工人面临持续的工作压力（难缠的甲方、不讲理的老板、无尽的需求变更），需要一个**低成本、即时可得**的情绪宣泄出口。现有的解决方案：
- 刷短视频：被动消费，没有参与感
- 玩大型游戏：门槛高、时间长、无法碎片化
- 现有解压小程序：要么纯暴力无共鸣，要么玩法老旧无爽感

### 1.2 目标用户

- **目标用户**：22-35岁互联网/白领打工人
- **用户特征**：工作压力大、熟悉职场梗、活跃在微信生态、有分享欲但怕社死
- **核心痛点**：
  1. 情绪无处发泄，憋在心里影响状态
  2. 碎片时间想玩点什么，但不想动脑
  3. 想吐槽职场，但不敢发朋友圈

### 1.3 市场机会

- 微信小游戏月活数亿，解压品类活跃
- 弹球/物理玩法在微信有成功先例（《最强弹一弹》《物理弹球正版》DAU百万级）
- **细分赛道空白**：尚无"职场梗 + 物理弹射 + 社交分享"的组合产品
- 2024-2025年"解压三件套"验证了情绪经济的巨大市场

## 二、解决方案

### 2.1 核心思路

> **用简化物理弹射提供即时爽感，用预置职场梗角色提供内容共鸣，用搞笑吐槽分享图提供社交裂变。**

玩家选择一名"打工人公敌"角色，拖拽发射击毁代表工作压力的建筑/障碍物，命中时弹出随机吐槽台词，通关后生成分享图发朋友圈/群聊。

### 2.2 方案详情

#### 游戏机制（愤怒小鸟式抛物线弹射）

```
用户流程：
选择关卡 → 选择角色 → 拖拽拉弓瞄准 → 松手发射 → 抛物线飞行 → 碰撞建筑 → 建筑倒塌 → 击中目标 → 弹出吐槽 → 结算 → 生成分享图
```

- **弹射方式**：手指拖拽拉弓（类似愤怒小鸟），设置角度和力度，松手发射
- **物理规则**：抛物线轨迹 + 重力影响 + 碰撞反弹
  - 角色飞行轨迹受重力影响呈抛物线
  - 碰撞建筑后根据角度和力度产生反弹或穿透
  - 建筑由砖块/木板堆叠，受碰撞后产生倒塌/碎裂效果
  - 建筑倒塌可能引发连锁反应（多米诺效应）
- **胜负条件**：击毁所有"猪/目标"即通关

**与简化弹球的区别**：
- 需要抛物线轨迹计算（重力加速度）
- 建筑是堆叠结构，需要考虑支撑关系和倒塌逻辑
- 视觉反馈更丰富（建筑倒塌、碎片飞溅）
- 操作手感更接近愤怒小鸟的经典体验

#### 预置角色（打工人公敌）

| 角色 | 形象特征 | 代表痛点 |
|---|---|---|
| 秃头老板 | 地中海、西装、拿保温杯 | 无理要求、画大饼 |
| 凌晨发消息的甲方 | 黑眼圈、抱手机、西装 | 随时打扰、需求变更 |
| 改需求的产品经理 | 格子衫、拿PRD、眼镜 | 反复修改、加功能 |

#### 目标/障碍物（工作压力具象化）

| 关卡 | 场景 | 目标 | 障碍物 |
|---|---|---|---|
| 第1关：办公室 | 办公隔间 | 堆积的文件山 | 显示器、咖啡杯 |
| 第2关：会议室 | 会议室 | 写满需求的黑板 | 投影仪、椅子 |
| 第3关：抽象空间 | 几何风格 | 截止日期的日历 | 方块、三角 |

#### 吐槽系统

- **触发时机**：击中目标时随机弹出
- **内容风格**：搞笑风 + 阴阳怪气风
- **数量**：Demo阶段30条，覆盖常见职场场景
- **示例**：
  - "这个需求很简单，怎么还没做完？" → 击中弹出："您说得对，我这就去投胎重学"
  - "今晚加个班，明天早上要" → 击中弹出："好的，我这就去申请工伤"
  - "方案再改一版，要大气" → 击中弹出："大气？我这就去充个会员"

#### 分享裂变机制

- **分享图内容**：角色形象 + "我砸了XXX" + 一句精选吐槽 + 二维码
- **分享场景**：通关后自动生成，一键分享到朋友圈/群聊
- **激励设计**：分享后可解锁隐藏角色（Demo阶段暂不实现，预留接口）

### 2.3 关键特性

1. **零门槛即开即玩**：微信小程序，无需下载，3秒进入游戏
2. **预置角色自带梗**：每个角色都是打工人的"老熟人"，看到就想砸
3. **吐槽精准扎心**：文案团队深挖职场痛点，每条吐槽都能引发"这不就是我吗"的共鸣
4. **物理反馈爽感**：碰撞音效+震动+建筑倒塌动画，提供即时多巴胺
5. **分享图即梗图**：分享出去的不是广告，是打工人朋友圈的"嘴替"

### 2.4 用户体验

**核心循环（单次体验，约1分钟）**：

```
打开小程序 → 看到"今天想砸谁？" → 选择秃头老板 → 
拖拽瞄准堆积的文件山 → 发射！ → 老板弹射出去撞倒文件 → 
弹出吐槽"您说得对，我这就去投胎重学" → 
文件山倒塌，通关！ → 生成分享图"我砸了秃头老板" → 
分享到"吐槽专用"群 → 同事回复"哈哈哈哈"
```

**情感曲线**：
- 选择角色：期待（"今天就砸他了"）
- 拖拽瞄准：专注
- 发射命中：爽感（破坏快感）
- 吐槽弹出：共鸣+笑出声
- 分享成功：社交满足

## 三、可行性分析

### 3.1 技术可行性

**评估**：⚠️ **可行，但挑战加大**

| 模块 | 技术方案 | 难度 | 备注 |
|---|---|---|---|
| 微信小程序框架 | 微信原生小游戏 / Cocos Creator导出 | 低 | 开发负责，团队熟悉即可 |
| 物理引擎 | Matter.js（轻量级2D物理引擎） | **中高** | 支持抛物线、重力、碰撞、刚体堆叠和连锁倒塌 |
| 渲染 | Canvas 2D | 低 | 2D卡通风格，性能友好 |
| 角色/场景美术 | 预置PNG素材 | 中 | 美术负责，建议简化风格降低工作量 |
| 音效 | 预置音频文件 | 低 | 开发+策划协作 |
| 分享图生成 | Canvas绘制+wx.canvasToTempFilePath | 中 | 开发负责，注意低端机性能 |
| 排行榜 | 微信开放数据域 | 低 | 开发负责，API成熟 |

**关键难点**：
1. **抛物线物理计算**：重力加速度、发射力度与距离的关系、碰撞反弹角度——需要反复调参才能手感舒适
2. **建筑堆叠与倒塌**：愤怒小鸟的爽感来自"多米诺倒塌"，Matter.js虽然支持刚体堆叠，但倒塌的"戏剧感"需要关卡设计+物理参数双重调校
3. **性能优化**：多个刚体同时碰撞计算，低端安卓机可能掉帧

**解决思路**：
1. Matter.js已内置重力、碰撞、刚体堆叠，开发只需调参无需自研物理
2. 建筑倒塌的"戏剧感"主要靠美术（碎裂动画）+ 音效弥补，不完全依赖物理精度
3. 限制每关刚体数量（砖块+木板≤30个），确保性能
4. 如果Day 5物理手感仍不达标，降级为"简化抛物线"（预设几条轨迹线，玩家选择角度）

### 3.2 商业可行性

**评估**：⚠️ **有挑战，但模式清晰**

| 维度 | 分析 |
|---|---|
| 盈利模式 | 免费 + 激励视频广告（复活、解锁角色） |
| 变现前提 | 需要DAU到万级才有意义 |
| 获客成本 | 靠分享裂变降低，几乎为零 |
| 市场潜力 | 微信小游戏月活数亿，职场人群占比高 |

**现实评估**：
- Demo阶段（半个月）不考虑变现，只验证可行性
- 如果分享率>10%、单局时长>30秒，说明有变现潜力
- 广告变现是成熟的IAA模式，接入成本低

### 3.3 资源可行性

**评估**：⚠️ **有挑战，需要严格控范围**

| 资源 | 需求 | 获取方式 |
|---|---|---|
| 开发人力 | 2-3人，10个工作日 | 自有团队 |
| 美术资源 | 3个角色 + 3个场景 + UI + 分享图模板 | 自有美术或外包（建议简化风格降低工作量） |
| 音效资源 | 碰撞音效×5 + 背景音乐×1 + 发射音效 | 免费音效库（如 freesound.org） |
| 文案内容 | 30条吐槽台词 | 团队共创，1天可完成 |
| 服务器 | 排行榜+分享图，几乎无服务端 | 微信云开发或静态托管 |

**关键约束**：
- 半个月 = 10个工作日，时间非常紧
- 如果团队只有1个开发+1个美术，必须砍掉非核心功能

## 五、风险与应对

### 5.1 风险清单

| 风险 | 概率 | 影响 | 应对策略 |
|---|---|---|---|
| 时间不够，Demo质量不达标 | **高** | **高** | 严格控制MVP范围；第1周完成核心循环，第2周填充内容；预留2天缓冲 |
| 微信审核不通过 | **中** | **致命** | 预置卡通角色（非真人）；避免"杀、死、血"等敏感词；击中反馈用"弹飞、消失"替代暴力；提前提交审核 |
| 物理手感差，玩起来不爽 | **中** | **高** | 参考弹球爆款参数；第1周每天 playable test；手感不达标时降级为"固定轨迹"模式 |
| 吐槽文案不够好笑 | **中** | **中** | 团队内部投票筛选；找10个目标用户测试反馈；保留20条最好的 |
| 分享率低于预期 | **高** | **中** | 分享图设计要像梗图而不是广告；预留优化空间（如分享解锁角色） |
| 美术资源制作耗时超预期 | **中** | **高** | 采用极简几何风格+表情包化角色，降低美术工作量；必要时用色块+文字替代精细绘画 |

### 5.2 应急预案

- **如果第5天核心循环还没跑通**：砍掉第3关，只做2关；砍掉排行榜，只做分享图
- **如果审核被拒**：根据反馈修改文案/特效，3天内重新提交；如果因"攻击性内容"被拒，将所有"砸"改为"弹飞"
- **如果物理手感调不出来**：切换为"点击固定位置发射"模式，放弃自由拖拽角度
- **如果美术进度滞后**：用emoji风格或简笔画替代精细角色，后续迭代优化

### 本地图片替换功能设计（替换打击目标）

**功能描述**：
用户可在关卡准备界面点击"换目标脸"按钮，从手机相册选择一张图片，系统自动裁剪为圆形头像，替换当前关卡中"被打击目标"（猪）的头部图片。图片仅保存在本地缓存，不上传服务器；分享图始终使用预置卡通目标形象，不带用户上传的图片。

**为什么这样设计**：
1. **核心爽感**：用户把讨厌的人/事的照片作为"被砸对象"，宣泄感直接拉满
2. **规避审核**：分享图不带真人肖像，不构成"用户生成内容传播"
3. **规避肖像权**：不上传服务器，纯本地使用，平台无责任
4. **开发成本低**：利用小程序原生API，无需后端服务

**用户流程**：
```
关卡准备界面 → 点击"换目标脸" → 选择相册图片 → 自动裁剪圆形 → 预览效果 → 确认使用 → 目标头部显示用户图片
```

**界面示意**：
```
┌─────────────────────────────┐
│  第1关：办公室文件山          │
│                             │
│    [弹射角色：默认拳头]      │
│         ↓                   │
│    [目标：用户上传的老板照片] │  ← 头部是用户图片，身体是预置卡通
│         ↓                   │
│    [建筑：文件山]            │
│                             │
│  [开始]  [换目标脸 📷]       │
└─────────────────────────────┘
```

**技术要点**：
- `wx.chooseImage` 选择本地图片
- `wx.getFileSystemManager` 读取文件
- Canvas 裁剪为圆形头像（遮罩）
- `wx.setStorageSync` 本地缓存裁剪后的头像（key: `user_target_face`）
- 游戏渲染目标时，优先使用本地缓存头像作为头部贴图，无缓存则使用预置目标形象
- 分享图生成时**强制使用预置目标形象**，不带用户上传的图片
- 每关可独立设置目标脸，或全局统一设置
