# 胡了卜特殊事件 Demo 第一版设计

- 日期：2026-06-13
- 任务：T163
- 状态：已确认方向，进入实现计划

## 1. 目标

在朋友试玩版中加入可感知的 Roguelike 特殊事件，但不提前实现完整高阶周目系统。事件应让玩家在关前做一次短选择：拿稳定收益、补救场道具，或主动给下一关加一点压力换更高收益。

## 2. 触发节奏

- 事件只出现在默认玩家页。
- 第 6、8、10 关开始前触发事件选择。
- 每个触发点只弹一次，玩家选择后继续进入对应关卡。
- 教学关和第 5 关不触发事件，避免打断基础规则学习。
- 事件不在牌桌中途打断，不影响正在进行的点击、入槽和组合操作。

## 3. 第一版事件池

第一版只做 3 类事件选项，文案可换，但效果要稳定：

| 类型 | 示例 | 效果 |
| --- | --- | --- |
| 稳定收益 | 路遇老雀 | 直接获得铜钱 |
| 救场补给 | 旧牌匣 | 增加洗牌、撤回或丢弃次数 |
| 主动加压 | 加注一局、暗灯牌局 | 下一关附加小词缀，通关收益提高 |

## 4. 第一版词缀

只实现能在 HTML Demo 中低风险验证的轻量词缀：

| 词缀 | 效果 | 展示 |
| --- | --- | --- |
| 禁洗牌 | 下一关不能使用洗牌 | HUD/状态栏提示 |
| 禁透视 | 下一关不能使用透视 | HUD/状态栏提示 |
| 高压牌山 | 下一关牌量或高压模板倾向提高 | HUD/状态栏提示 |

负面效果必须来自玩家主动选择，不做无预警惩罚。

## 5. 状态设计

- `run` 级状态记录已经触发过的事件关卡。
- `pendingSpecialEvent` 表示当前关前等待选择的事件。
- `pendingLevelModifier` 表示玩家选择后要应用到下一关的词缀。
- `activeLevelModifier` 表示当前关正在生效的词缀，用于 HUD、工具按钮禁用和关卡生成参数。
- 事件效果只影响下一关，关卡结束后清空，避免长期状态污染。

## 6. UI 设计

- 复用现有 overlay，不新增复杂页面。
- 标题使用事件名，如 `路遇老雀`、`旧牌匣`、`加注一局`。
- 三个按钮分别表达收益或代价，按钮文案必须能直接看懂结果。
- 事件选择后用状态栏短提示说明获得了什么，进入关卡后 HUD 显示当前词缀。
- 移动端要保证弹层按钮不遮挡卡槽和底部道具栏。

## 7. 非目标

- 不实现完整 12 个随机事件。
- 不实现 Boss 试炼的独立目标系统。
- 不实现永久能力卡槽压缩。
- 不实现事件奖励品质系统。
- 不修改 Cocos 正式工程。

## 8. 验收标准

- 第 6、8、10 关前会出现事件选择。
- 选择铜钱或道具选项会立即改变 run 状态。
- 选择词缀选项会影响对应关卡，并在 HUD/状态栏显示。
- 禁洗牌/禁透视会让对应工具在当前关不可用。
- 高压牌山不会破坏当前第 5-10 关渐进曲线和首轮可点上限。
- 源 HTML 和站内静态 Demo 行为一致。
- 自动化测试、脚本语法检查、桌面和 390px 移动端浏览器检查通过。
