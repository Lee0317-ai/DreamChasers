# 胡了卜路线型奖励池扩展设计

- 日期：2026-06-14
- 任务：T169
- 状态：已确认实现方向

## 1. 目标

把当前胡了卜 run 内奖励从“基础道具 + 单次分数补丁”推进到真正有 build 倾向的路线型奖励池，让朋友试玩时能明显感受到自己是在往某种打法堆，而不是只捡便宜数值。

## 2. 现状问题

当前 `rewards.json` 只有 10 个奖励，主要由以下几类构成：

- `吃 / 碰 / 杠` 单项分数奖励
- 单次 `洗牌 / 撤回 / 透视`
- `备用槽 / 护符`
- 立即加铜钱

这些奖励能补基础手感，但还不够形成清晰路线：

- `胡流` 奖励几乎没有
- `道具流` 只有次数，没有风格差异
- `信息流` 只有透视次数，没有“更会读牌”的成长感
- 奖励卡展示层也看不出当前奖励偏哪条路线

## 3. 设计原则

1. 不破坏 8 格主槽和当前主线可玩性。
2. 奖励优先改变打法，不优先继续加纯铜钱。
3. 每条路线第一版都用“轻量但可感知”的效果，不引入复杂新状态机。
4. 路线感既要来自 reward effect，也要来自奖励卡展示和已选奖励区。

## 4. 第一版路线

第一版至少保留并明确以下 6 条路线：

| 路线 | 核心感觉 | 第一版奖励方向 |
| --- | --- | --- |
| 吃流 | 顺子滚动、频繁起手 | `chi` 分数、吃后补工具、吃后保牌 |
| 碰流 | 稳定清槽、明牌推进 | `peng` 分数、碰后补铜钱、碰后补护符 |
| 杠流 | 高风险开山、震落压牌 | `gang` 分数、杠后额外铜钱、杠后补工具 |
| 胡流 | 清槽爆发、强回合收束 | `hu` 分数、胡后额外震落收益、胡后清河收益 |
| 道具流 | 更依赖洗牌/撤回/丢弃 | 额外次数、单类强化、混合补给 |
| 信息流 | 更会读牌和等牌 | 透视次数、听牌提示强化、记牌器高亮强化 |

## 5. 实现范围

本轮只做“奖励池路线化第一版”，不新增完整被动系统。

实现方式：

1. 扩 `rewards.json`
   - 从 10 个奖励扩到一组更能分流的奖励池。
   - 每个奖励保留现有 `category / effects` 结构。
   - 新增更明确的 `hu / tool / info / economy / rescue` 细分类别即可，不强行改 schema。

2. 扩原型 `pickReward`
   - 只使用已有可承载 effect：
     - `reserve_limit_delta`
     - `shield_delta`
     - `coin_delta`
     - `tool_delta`
     - `combo_score_bonus`
   - 不在 T169 里发明新的底层 effect 类型，避免把任务膨胀成新规则系统。

3. 扩奖励展示
   - 奖励卡显示路线标签。
   - 已选奖励区按“奖励名 + 路线标签”展示。
   - 在 `/games/hulebu` 外层壳的“已选奖励”数字维持不变，不新增复杂摘要。

## 6. 奖励池策略

### 6.1 数量目标

把当前奖励池从 10 个扩到至少 16 个，理由：

- 6 条路线每条只有 1 张牌不够形成分叉
- 20 关主线有 6 个奖励节点，需要玩家多跑几轮仍能看到变化

### 6.2 推荐构成

- 吃流：2-3 张
- 碰流：2-3 张
- 杠流：2-3 张
- 胡流：2 张
- 道具流：3-4 张
- 信息流：2 张
- 救场/经济：保留 2-3 张兜底

### 6.3 不做的奖励

- 不恢复主槽扩容
- 不做改变关卡结构的永久奖励
- 不做复杂触发链，比如“连续两次碰后下一次胡翻倍”
- 不做局外成长和局内奖励混用

## 7. UI 表达

奖励弹层的每张卡第一版增加：

- 奖励名
- 路线标签，例如 `吃流`、`杠流`、`信息流`
- 1 行效果说明

已选奖励区：

- 保留 pill 结构
- 文案改为 `奖励名 · 路线`

这样玩家在 run 中能直接读出自己当前偏向哪条 build。

## 8. 验收口径

- 奖励配置不再只有 10 个基础奖励
- 奖励类别能覆盖 `吃 / 碰 / 杠 / 胡 / 道具 / 信息`
- 奖励弹层和已选奖励区能看出路线类别
- 不破坏现有 20 关奖励节点和 8 格主槽口径
- 测试、脚本语法、桌面和 390px 移动端检查通过
