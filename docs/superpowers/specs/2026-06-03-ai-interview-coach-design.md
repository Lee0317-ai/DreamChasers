## 1. 产品定位

`AI 面试助手` 是一个网页小工具，面向面试官和面试者两类用户。用户输入岗位 JD、候选人简历和补充参数后，系统生成一份可下载 HTML 面试作战包，并可进入虚拟面试模式，通过大模型进行一问一答的模拟面试，最后生成结构化复盘报告。

该工具不是普通题库生成器，而是 `岗位能力地图 + 简历证据矩阵 + 双视角面试作战包 + 虚拟面试复盘` 的组合工具。

## 2. 核心用户

### 2.1 面试者

目标是准备真实面试。用户希望知道：

- 这个岗位大概率会问什么。
- 自己简历里哪些经历最容易被追问。
- 每道题应该如何回答，如何补充项目细节和结果数据。
- 虚拟面试后，自己的回答哪里空泛、哪里有风险、下一轮怎么改。

### 2.2 面试官

目标是提升面试准备质量。用户希望知道：

- 根据 JD 和简历，应该重点考察哪些能力。
- 每个能力点应该问什么问题、怎么追问、怎么评分。
- 候选人简历里的强匹配、弱匹配、疑点和风险在哪里。
- 如何避免不合规或与岗位无关的问题。

## 3. MVP 范围

第一版做三个闭环：

1. 输入 JD、简历和参数。
2. 生成双入口 HTML 面试作战包。
3. 进入文本虚拟面试，并在结束后生成复盘 HTML。

第一版支持：

- 双入口：`我是面试官`、`我是面试者`。
- 输入方式：粘贴岗位 JD、粘贴简历文本、上传简历图片。
- 参数配置：岗位方向、职级、轮次、面试风格、时长、题目数量、语言、重点追问方向。
- 生成内容：岗位能力地图、简历证据矩阵、题目、参考答案、追问、评分标准、风险提醒。
- 虚拟面试：文本聊天式问答，大模型根据用户回答动态追问。
- 下载 HTML：生成结果和虚拟面试复盘均可下载为本地 HTML。

第一版不做：

- 实时语音面试。
- 企业 ATS 接入。
- 批量候选人筛选。
- 用户账号、历史记录和云端简历库。
- 简历优化改写。
- PDF、Word 或 PPT 导出。
- 自动录用、淘汰或候选人排名。
- 真实面试中的实时作弊辅助。

## 4. 用户流程

### 4.1 入口

工具挂在网页工具频道：

- 入口卡片：`AI 面试助手`
- 推荐路径：`/tools/ai-interview-coach`
- 分类：`AI 能力`、`办公效率`、`求职招聘`

首页卡片文案建议：

> 输入岗位 JD 和简历，生成双视角面试作战包。支持虚拟面试、动态追问和 HTML 复盘下载。

### 4.2 参数配置

用户进入后先选择身份：

- 面试者模式。
- 面试官模式。
- 双视角模式。

然后填写：

- 岗位 JD。
- 简历文本。
- 简历图片上传。
- 岗位方向：前端、后端、产品、运营、设计、销售、AI 工程、其他。
- 岗位级别：实习、初级、中级、高级、专家、管理岗。
- 面试轮次：HR 初筛、技术一面、业务二面、主管面、终面。
- 面试风格：温和、标准、严格、压力型。
- 题目数量：5、10、15、自定义。
- 虚拟面试时长：5、10、20、30 分钟。
- 语言：中文、英文、中英混合。
- 重点方向：项目深挖、技术能力、业务理解、沟通协作、稳定性、转岗动机。

### 4.3 生成报告

系统先结构化解析：

1. JD 能力项。
2. 简历经历和证据点。
3. JD 与简历匹配关系。
4. 面试风险和追问方向。

然后生成 HTML 作战包：

- 封面信息。
- 岗位能力地图。
- 简历证据矩阵。
- 面试官版题库和评分卡。
- 面试者版回答框架。
- 高频追问链。
- 专业领域实战例子和行业用法说明。
- 风险与合规提醒。
- 反问问题建议。

### 4.4 虚拟面试

虚拟面试第一版使用文本对话。

流程：

1. 用户点击 `进入虚拟面试`。
2. AI 根据已解析的 JD、简历和参数生成首题。
3. 用户回答。
4. AI 判断回答质量，并选择继续追问或进入下一题。
5. 到达题数或时间后结束。
6. 系统生成复盘：能力评分、强项、弱项、空泛回答、建议补充细节、下一轮准备建议。

虚拟面试的 AI 面试官不应该只按固定题库问，而应根据用户回答动态决定：

- 是否追问数据。
- 是否追问个人贡献。
- 是否追问失败复盘。
- 是否追问技术细节。
- 是否追问业务影响。
- 是否切换到下一个能力项。

## 5. 差异化设计

### 5.1 双视角镜像

同一份输入同时生成面试官版和面试者版。面试官看到考察点、追问和评分；面试者看到回答框架、简历证据和避坑提醒。

### 5.2 JD x 简历证据矩阵

每道题都要能追溯到：

- 来自 JD 的哪个岗位要求。
- 来自简历的哪段经历。
- 是强匹配、弱匹配、缺失还是疑点。

这能减少泛泛而谈，让报告更像专业面试准备材料。

### 5.3 追问链

每个核心问题至少包含：

- 初始问题。
- 第一层追问：验证真实性。
- 第二层追问：验证方法和取舍。
- 第三层追问：验证结果和复盘。

面试者版同步给出如何补充细节。

### 5.4 结构化评分卡

面试官版输出 1-5 分评分锚点。评分只作为面试辅助，不输出自动录用或淘汰建议。

### 5.5 复盘 HTML

虚拟面试结束后，系统不只给一句评价，而是输出可下载复盘：

- 问答记录。
- 每题评分。
- 回答中的证据点。
- 空泛回答片段。
- 推荐改写版本。
- 下一轮练习计划。

### 5.6 专业实战补充

面试提纲不只列问题，还应给出专业领域的简单实战例子和行业用法说明。比如前端岗位可以补充性能优化、组件拆分、埋点、异常监控等常见场景；后端岗位可以补充接口限流、缓存穿透、数据库索引、任务队列等场景；运营岗位可以补充转化漏斗、活动复盘、用户分层和内容分发等场景。

该能力的目标不是写长篇教程，而是帮助用户理解题目背后的真实工作语境，并给面试者提供可迁移的回答素材。

## 6. AI 能力拆分

建议把大模型能力拆成多个内部 skill / prompt 模块：

- `jd-parser`：解析岗位职责、硬技能、软技能、经验要求和业务目标。
- `resume-parser`：解析简历项目、角色、动作、结果、技术栈和疑点。
- `match-matrix`：建立 JD 与简历证据矩阵。
- `question-planner`：按能力项生成问题计划。
- `interviewer`：虚拟面试官，负责提问和追问。
- `answer-coach`：面试者回答建议。
- `scorecard`：结构化评分和改进建议。
- `html-report`：把结构化数据渲染成 HTML 报告。

第一版不建议让模型直接生成完整 HTML。更稳的方式是：

1. 模型输出 JSON。
2. 前端用固定模板渲染 HTML。
3. 用户下载模板渲染后的 HTML 文件。

## 7. 技术可行性

### 7.1 前端

可以作为独立网页小工具接入现有工具频道：

- 路由：`apps/web/src/app/tools/ai-interview-coach/page.tsx`
- 模块：`apps/web/src/modules/tools/ai-interview-coach/**`
- 入口数据：`apps/web/src/components/portal-data.ts`

前端主要页面：

- 参数表单。
- 文件上传区。
- 生成进度。
- 报告预览。
- 虚拟面试聊天区。
- HTML 下载按钮。

### 7.2 后端 API

建议新增 API 路由：

- `POST /api/tools/ai-interview-coach/analyze`：解析 JD 和简历。
- `POST /api/tools/ai-interview-coach/report`：生成结构化报告数据。
- `POST /api/tools/ai-interview-coach/interview/start`：创建虚拟面试会话。
- `POST /api/tools/ai-interview-coach/interview/message`：提交回答并获取追问。
- `POST /api/tools/ai-interview-coach/interview/summary`：生成复盘。

第一版可以不做持久化，所有会话数据保存在浏览器内存或临时请求上下文中。

### 7.3 图片上传

简历图片上传第一版可以作为 AI 解析输入。若图片质量差，页面提示用户补充粘贴文本。

### 7.4 实时语音

实时语音可作为第二阶段。第一版先做文本虚拟面试，降低权限、兼容性和成本风险。

## 8. 合规和边界

- 明确文案：本工具生成面试准备和辅助材料，不做录用决策。
- 面试官模式避免生成年龄、婚育、健康、民族、宗教、地域歧视等敏感问题。
- 简历默认不保存；若后续保存历史记录，必须有明确授权。
- 虚拟面试不提供真实面试中的实时作弊用途。
- 评分卡只辅助复盘，不替代人工判断。

## 9. 商业化建议

第一版可以采用免费限次：

- 免费：每天 1-3 次报告生成，文本虚拟面试 1 次。
- 限次或积分：图片简历解析、多轮虚拟面试、长报告、高级评分卡。
- 后续付费：语音虚拟面试、企业面试官评分卡、批量岗位模板、历史报告库。

规划阶段验收：

- 本设计稿覆盖双入口、报告生成、虚拟面试、参数配置、技术边界和合规边界。
- 模块文档目录建立。
- 任务池登记为 T106。
- 不产生业务代码改动。

后续 MVP 验收建议：

- 用户能在工具页输入 JD、简历和参数。
- 系统能生成结构化报告预览。
- 用户能下载 HTML。
- 用户能进入文本虚拟面试并完成至少 5 轮问答。
- 虚拟面试后能生成复盘 HTML。
- 敏感问题过滤和免责声明可见。
- 基础 lint、typecheck、build 和浏览器桌面/移动检查通过。

## 12. 主要风险

- 成本：图片解析和多轮问答会增加模型调用成本，需要限次。
- 质量：如果没有结构化中间层，输出容易泛泛而谈。
- 隐私：简历信息敏感，第一版应默认不保存。
- 合规：面试官模式必须避免敏感问题和自动决策表达。
- 范围：语音、历史库、企业筛选容易扩大范围，应后置。

## 13. 推荐结论

建议作为网页小工具候选方向入池，优先级 P2。该工具与现有 AI 内容转换方向有协同，但用户场景更明确，具备搜索流量和付费空间。第一版应先做文本报告和文本虚拟面试，不要一开始做实时语音和企业招聘系统。
