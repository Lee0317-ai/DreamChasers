# 胡了卜残局收官设计规格

**日期**：2026-06-01  
**关联任务**：T094  
**状态**：设计稿  
**范围**：朋友试玩 Demo 后续改造和正式工程规则方向

## 1. 设计结论

胡了卜不应把 `卡槽必须清空` 作为所有关卡的默认胜利条件。默认规则应改成：

- 普通关：牌桌清空后，如果卡槽为空，直接过关；如果卡槽有残张，进入 `残局收官`。
- 教学关：必须发动本关教学组合，不能只把牌点进槽位就过关。
- Boss 关和特殊契约：可以额外要求清槽、胡牌或指定目标，但必须由配置明确声明。

`残局收官` 是牌桌清空后的短决策。它把孤张从无解惩罚转成玩家的构筑资源和代价选择。

## 2. 核心循环

当前关卡处于 `playing` 时，玩家持续点击可用牌入槽，并手动发动 `碰 / 吃 / 杠 / 胡`。

当牌桌清空时，按以下顺序结算：

1. 如果是教学关，并且本关教学组合尚未发动，继续停留在当前关，提示玩家点击对应组合按钮。
2. 如果本关有 Boss 目标或特殊契约，先检查目标是否完成；未完成则按目标失败或继续提示处理。
3. 如果卡槽为空，进入正常胜利和奖励流程。
4. 如果卡槽有残张，进入 `残局收官`，不直接失败。

这样能保留槽位压力，同时避免孤张把普通关变成生成器死局。

## 3. 残局收官三选一

### 3.1 弃牌通关

玩家选择直接清掉槽内残张并过关。

- 优点：最快，适合朋友试玩和新手。
- 代价：本关奖励降档，或少给铜钱/评分。
- Demo 第一阶段：优先实现，作为默认兜底。

### 3.2 选作牌引

玩家从槽内残张中选 1 张作为 `牌引` 带到下一关。其余残张清掉。

- 作用：下一关生成器围绕牌引做轻度倾斜。
- 数牌：同牌权重最高，相邻牌次之，同花色再次之。
- 字牌：同字牌权重最高，其他字牌小幅提高。
- 限制：牌引只影响下一关，不跨多关堆叠；倾斜比例需要上限，避免下一关变成保送。
- Demo 第一阶段：实现一个轻量版，顶部 HUD 显示当前牌引，下一关生成时做低强度偏置。

### 3.3 收入牌河

玩家把残张收入 `牌河`。牌河是跨关的残局资源池，后续可以凑出 `吃 / 碰 / 杠 / 胡` 素材兑换奖励或救场。

- 优点：最有长期构筑感。
- 风险：UI 和规则复杂度最高。
- Demo 第一阶段：只在设计和 UI 文案中保留方向，不实现兑换系统。
- 正式工程：牌河可兑换丢弃次数、撤回次数、铜钱、临时护符或关卡内补牌机会。

## 4. 教学关规则

前 4 关必须从“点牌入槽教学”改成“发动组合教学”。

- 第 1 关：教学 `碰`。玩家必须让 `碰` 按钮亮起并点击发动，才算完成。
- 第 2 关：教学 `吃`。玩家必须发动一次 `吃`。
- 第 3 关：教学 `杠`。玩家必须发动一次 `杠`。
- 第 4 关：教学 `胡`。玩家必须用 8 格主槽发动一次 `胡`。

教学关不强制卡槽清空。教学目标完成后，如果牌桌仍有少量牌，可以直接进入通关或用固定脚本清理；朋友试玩阶段应优先保持教学短、清楚、低压力。

## 5. 失败和残张边界

`槽位满` 不应立即等于失败。失败判定按以下优先级：

1. 槽位满但存在可发动组合：不失败，提示发动组合。
2. 槽位满且没有组合，但还有 `丢弃 / 撤回 / 洗牌` 等可用救场：不失败，提示可用救场。
3. 槽位满、无组合、无救场：失败。
4. 牌桌清空但槽内有残张：进入 `残局收官`，不是失败。

Boss 关可以配置更严格条件，例如 `牌桌清空 + 目标达成 + 卡槽清空`，但这不是普通关默认规则。

## 6. 丢弃工具

`丢弃` 不应自动丢最后一张。它应该进入选择模式：

- 点击 `丢弃` 后，槽位牌进入可选状态。
- 玩家点击任意一张槽位牌，丢弃该牌并消耗 1 次。
- 再次点击 `丢弃` 或点击空白区域可取消选择模式。
- 被丢弃的牌不进入牌河，也不能作为牌引。

这个规则让丢弃成为决策，而不是系统替玩家做选择。

## 7. 记牌器

玩家页必须提供可见记牌器，因为残局收官和牌引都依赖剩余牌判断。

第一阶段建议：

- 顶部 HUD 显示 `万 / 条 / 筒 / 字` 四类剩余总数。
- 可展开查看 1-9 点数和字牌余量。
- 记牌器只显示数量，不显示位置，保留透视道具的价值。

记牌器用于支撑这些判断：

- 孤张是否还有补牌机会。
- 当前牌是否值得作为牌引。
- 是否应该丢弃、等待、追顺子或转向碰/杠。

## 8. 牌面可读性

下一轮实现需要提升玩家页牌面可读性：

- 教学关牌量少，应使用更大的牌面和点击热区。
- 正式密集关可以保留高牌量，但需要把牌面符号和点击热区放大到手机可辨认。
- 牌面放大优先影响玩家页，不要求调牌器完全同尺寸。
- 放大后要重新检查首屏可见、卡槽、右侧道具和记牌器是否仍能同时存在。

## 9. 状态和数据建议

推荐新增或预留这些状态概念：

- `phase: "playing" | "endgame" | "reward" | "failed" | "won"`
- `requiredTutorialCombo?: "peng" | "chi" | "gang" | "hu"`
- `completedTutorialCombos: Record<string, number>`
- `residualTiles: TileId[]`
- `carryGuideTile?: TileId`
- `riverTiles: TileId[]`
- `rewardGradeModifier: number`
- `discardSelecting: boolean`

实现时不必一次性引入完整正式模型。HTML Demo 可以先用最小状态承接交互，再在 Cocos/共享规则阶段抽象为正式数据结构。

## 10. 分阶段落地

### 第一阶段：朋友试玩 Demo 修正

- 教学关必须点击组合按钮才过关。
- 牌面和点击热区放大。
- `丢弃` 改成选择槽位任意一张。
- 玩家页补可见记牌器。
- 普通关清空牌桌但槽内有残张时弹出 `残局收官`。
- 收官先实现 `弃牌通关` 和 `选作牌引`。
- `收入牌河` 先作为后续方向记录，不做兑换。

### 第二阶段：牌河资源化

- 牌河跨关保存残张。
- 牌河中凑成组合后可兑换救场或奖励。
- 加入牌河上限或衰减，避免无限囤积。

### 第三阶段：契约和 Boss 扩展

- 普通关默认允许残张收官。
- 契约关可选择 `清场过关` 获取更高奖励。
- Boss 关可配置清槽、胡牌、目标组合和牌河限制。

## 11. 测试策略

后续实现任务应至少覆盖：

- 教学关未发动组合时，即使牌桌清空也不能过关。
- 发动对应教学组合后才进入胜利或奖励流程。
- 普通关牌桌清空但槽内有残张时进入 `endgame`。
- `弃牌通关` 清空残张并降低奖励质量。
- `选作牌引` 记录 1 张牌引，并在下一关 HUD 展示。
- `丢弃` 只能丢玩家选择的槽位牌。
- 记牌器在玩家页可见，且消除后数量更新。
- 移动端无横向溢出，牌面、卡槽、道具、记牌器和收官弹层不互相遮挡。
