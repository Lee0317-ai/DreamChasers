# 胡了卜密集牌山生成器原型

## 1. 目标

T050 在 `prototypes/config-playable/index.html` 中新增 `密集牌山` 模式，用来验证更接近目标玩法的牌山密度、层级遮挡和解锁节奏。

它和 `配置关卡` 模式的分工不同：

- `配置关卡`：直接读取 `levels.json` 中手写的低牌量关卡，用于校验配置、槽位、吃碰杠、奖励选择。
- `密集牌山`：基于当前关卡素材生成 50 张左右的牌和多层遮挡，用于观察牌山空间压力。
- `牌山调参`：仅在密集牌山模式显示的开发用面板，用于快速改变随机种子、牌量、同列堆叠、`胡` 包和字牌权重；它不是正式玩家 UI。

## 2. 生成规则

- 默认使用关卡 `id` 和 `order` 做确定性随机种子，同一关每次生成结果稳定；也可以通过 URL 参数或调参面板覆盖种子。
- 从当前关卡牌面收集可用的 `吃 / 碰 / 杠` 组合模式。
- 先生成随机轮廓和同格叠柱，再从当前可点击牌反推一条理论清牌路径。
- 按理论路径给每组牌分配组合包牌面，路径末尾允许 1-2 张孤张，因为胜利只要求牌山清空。
- 如果关卡配置了 `featuredCombos: ["hu"]`，生成器默认会插入一个 `3 + 3 + 2` 的 8 张胡牌包；调参时可以把 `胡包` 改为 0-4 个，用于观察胡牌出现率。
- 当 Boss 同时要求 `combo_count: hu` 时，重点胡牌包会复用为 Boss 胡牌目标，避免在同一层连续强塞两个 8 张胡牌包导致无可用位置。
- 同格叠柱完全覆盖下方牌，画面只显示顶牌和横向层数提示。
- 遮挡超过 5% 即不可点击，`blockedBy` 由生成后的矩形重叠自动计算。
- 生成后会自检解法：每一步必须可点击，且按路径入槽/消组时不能塞满 8 格主槽；`胡` 包按 8 张一次性消除。
- 调参 URL 参数为：`seed` 随机种子、`tiles` 牌量、`stack` 同列堆叠深度、`hu` 胡包数量、`honor` 字牌权重。例如：`?level=20&mode=mountain&seed=calibrate&tiles=58&stack=6&hu=2&honor=90`。

## 3. 当前验证结果

- 第 1 关密集模式生成 50 张牌，画面渲染 44 张，其中 6 张为同格叠柱下方隐藏牌。
- 第 1 关初始约 6 张可点击牌，理论路径 17 步，末尾包含 2 张孤张。
- 第 1-20 关密集模式会基于同一生成器生成牌山；第 20 关的解法校验已能识别 `胡` 目标。
- 第 20 关密集模式已验证可通过 `?level=20&mode=mountain` 直接打开，生成 54 张牌，其中 37 张被压住，初始 11 张可点击。
- 第 20 关已补充调参回归测试，验证 `?level=20&mode=mountain&seed=calibrate&tiles=58&stack=6&hu=2&honor=90` 会生成 58 张牌、至少 12 张同列堆叠牌、至少 2 个胡牌包，并提高字牌数量。
- 第 6 关密集模式已验证可生成 8 张可点击胡牌包，点击后 `胡 1` 亮起，执行后一次清空 8 个主槽格。
- 槽里保留孤张不影响胜利，最后一张牌山牌入槽后即可结算。

## 4. 已知边界

- 这是 HTML 原型层生成器，不是最终 Cocos/GDevelop 实现。
- 当前可解路径是贪心反推，不是完整最优解搜索；它保证至少一条理论通路，但不评估所有玩家选择分支。
- 牌面视觉仍是 CSS 临时样式，后续正式工程需要重做动画、音效、手感和美术资源。
